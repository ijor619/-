# Обновление на защищённую версию

## Обязательно перед запуском

1. Скопируйте `.env.example` в `.env`.
2. Заполните `BOT_TOKEN`.
3. Заполните `OWNER_ID` своим числовым Telegram user ID. Бот не запустится без него и отклонит всех остальных пользователей.
4. Если используется CScalp, создайте новый секрет длиной не менее 32 символов:

   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

5. Одновременно обновите серверные `cscalp.py`/`bot.py` и Windows-файл `cscalp_bridge.py`.
6. В `cscalp_bridge.ini` укажите тот же секрет в `key`. Старый мост не понимает подписанный протокол.
7. Установите зависимости:

   ```bash
   pip install -r requirements.txt
   ```

   На Windows рядом с CScalp:

   ```powershell
   pip install -r requirements-bridge.txt
   ```

## Что изменилось

- личный режим fail-closed по `OWNER_ID`;
- HMAC-подпись, nonce и TTL команд CScalp;
- ключ больше не передаётся в URL и не является именем relay-топика;
- строгая проверка тикера на сервере и мостике;
- очередь CScalp не теряет быстрые команды;
- скринер использует timestamp источника и не создаёт фиктивные точки в выходные;
- auto-mute считает уникальные рыночные события, а не количество доставок;
- исправлены потери хвоста дайджеста и журнала очистки;
- корректное завершение фоновых задач;
- пользовательские данные удалены из deploy-архива и исключены через `.gitignore`/`.dockerignore`;
- зависимости закреплены, добавлены регрессионные тесты.

## Проверка

```bash
PYTHONPATH=. python -m unittest discover -s tests -v
python -m compileall -q .
```

Для CScalp сначала выполните безопасную локальную проверку:

```powershell
python cscalp_bridge.py --test SBER
```

Затем запустите мост и отправьте владельцем бота `/cscalp SBER`.
