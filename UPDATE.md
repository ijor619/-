# Обновление 05.11.2026

## Установка на Bothost

1. Сохраните резервную копию действующей папки `data` и текущей версии кода. Остановите старый процесс бота перед запуском нового: одновременно должен работать один экземпляр.
2. Загрузите код из этого архива. Папка проекта — `stockbot`, команда запуска прежняя: `python bot.py`.
3. Сохраните прежние переменные окружения Bothost: `BOT_TOKEN`, `TINKOFF_TOKEN`, `OWNER_ID`, `CSCALP_KEY` и остальные ваши настройки. Новых обязательных переменных нет. Значения ключей в архив не включены.
4. Подключите прежнюю постоянную папку `data` по тому же пути, что до обновления (по умолчанию `/app/data` в Docker; при `DATA_FILE` — каталог этого файла). Архив намеренно не содержит `data/users.json`, чтобы не заменить действующие подписки старой копией. Если Bothost пересоздаёт файловую систему без постоянного диска, верните сохранённую папку `data` до запуска.
5. Запустите один экземпляр и проверьте `/list`, `/stats` и стакан. В `/list` должны появиться источник, время цены и база процента. Это локально проверенная сборка; на ваш Bothost она автоматически не установлена.

Опрос цен по умолчанию теперь раз в 30 секунд. Если в Bothost уже задан `CHECK_INTERVAL_SEC`, сохранится ваше значение. Telegram-алерт остаётся снимком на момент отправки; актуальную цену запрашивайте через `/list`.

## Что исправлено

- Направление сигнала задаётся числом в детекторе. Слово «покупки» в пояснении к крупной продаже больше не превращает её в сигнал роста. Отскок от отрицательного порога теперь описывается как движение **выше** порога.
- Кластеры сохраняют отпечатки сделок вместе с объёмами. Перекрывающиеся запросы и перезапуски не прибавляют уже учтённые объёмы. Учтена кратность одинаковых сделок на одном времени; поддержана дозагрузка последнего часа после короткого окна.
- Первая и последняя цены определяются по времени сделок, а не по сортировке ценовых уровней. Если порядок разных цен при одинаковой временной отметке неизвестен, направленный вывод не строится.
- Каждое событие имеет общий идентификатор для всех получателей. Рассылка одному событию 40 пользователям больше не создаёт 40 наблюдений для автофильтра. Повторная доставка одному пользователю не дублирует запись. Ограничение частоты учитывает сохранённый журнал после перезапуска.
- Цена и время старта оценки закреплены при обнаружении, до ожидания дайджеста. «Ход 15м» в `/stats` считается в сторону сигнала: для продажи падение цены даёт положительный результат. Указаны число оценённых и общее число событий.
- Замеры 5/15 минут используют сделки не позже соответствующей временной точки и не старше 60 секунд относительно неё. История опроса должна покрывать эту точку. Через 90 секунд ожидания без подходящих данных записывается пропуск; он не считается ни нулём, ни проигрышем. Направления разных сигналов в одном сообщении оцениваются отдельно.
- Неудачная отправка ценового алерта и пауза между алертами больше не поглощают переход порога. Дайджест проверяет текущие подписки и тихие часы, сохраняется при ошибке отправки.
- Стакан показывает время из ответа API. Неопределённая сторона сделки больше не считается продажей. Скринер сохраняет время котировки, а не время запроса; старые цены исключаются из расчёта. График показывает начало последней свечи.
- Дневные high/low и оценка VWAP для сигналов берутся из минутных свечей T‑Invest и сбрасываются при смене дня; справочник цен регулярно обновляется.

## Почему расходились скриншоты RUAL

Бот считал `(23,955 / 23,270 − 1) × 100 = 2,9437%` к официальному закрытию MOEX. В приложении 5800 × 23,88 = 138 504 ₽, а дневная прибыль 4611 ₽ соответствует базе `(138504 − 4611) / 5800 = 23,085 ₽` и результату около 3,4438%.

Т‑Банк описывает «за сегодня» как сравнение с ценами на 04:00 МСК: [официальная справка](https://www.tbank.ru/invest/help/educate/yield-analysis/about/profit-check/). Поэтому одинаковое название «за день» у прежнего бота и приложения скрывало разные базы.

С T‑Invest список, сводки и ценовые алерты теперь используют последнюю полную биржевую минутную свечу **до 04:00 МСК**, с поиском назад на выходные и праздники. Текущая цена и свечи явно запрашиваются биржевые. Это восстановление базы по рыночным данным, а не получение доходности вашей позиции из счёта. Цена 23,085 использована в тесте арифметики из скриншота; исторический ответ API для вашего счёта не проверен и в коде эта цена не зашита.

Если база 04:00 недоступна, сохраняется свежая цена T‑Invest, а резервная база MOEX явно подписывается. Если недоступна сама цена T‑Invest, резерв MOEX тоже подписан. Смена базы не создаёт ложный алерт. Возраст T‑Invest цены для алертов ограничен 90 секундами; свежесть не выдается за подтверждённый статус открытия биржи.

Скринер «1д», графическая линия предыдущего закрытия и дневной контекст сетапа сохраняют биржевое сравнение к официальному закрытию MOEX; это отдельно подписано. Их процент имеет другой период, чем база 04:00 в списке и алертах.

Разницу **текущих** цен 23,955 и 23,88 по исходным скриншотам однозначно объяснить нельзя: в старом алерте нет времени самой котировки. Возможны разные моменты получения или источники/виды цен. Новая сборка показывает источник и время, но не гарантирует побитовое совпадение с интерфейсом брокера: цены опрашиваются, приложение может использовать другую оценку позиции. Доступ к вашим счетам и торговые операции не добавлены.

Контракты источников: [MarketDataService](https://developer.tbank.ru/invest/services/quotes/marketdata/).

## Старая история

При первом запуске новый код сохраняет старые файлы в `signals.json.legacy-v1.bak` и `clusters.json.legacy-v1.bak` рядом с ними. Новые статистика и кластеры начинают накапливаться заново. Настройки в `users.json` не мигрируются и не сбрасываются.

Старые результаты нельзя достоверно восстановить: отсутствуют идентификаторы событий, точные времена замеров и порядок сделок; направление некоторых сигналов было ошибочным. Поэтому они не смешиваются с новой статистикой. При откате к прежнему коду сначала остановите бот и восстановите исходные файлы из отдельной резервной копии; формат v2 старый код не понимает.

## Проверка и пределы

Автоматические проверки находятся в `tests/test_regressions.py`: `python -m unittest discover -s tests -v`. Они не обращаются к Telegram, Bothost или брокерскому счёту. Проверены повторы и перезапуск, направление, пропущенные замеры, несколько получателей, переход 04:00, праздники, резервный источник и ошибки отправки. Проверена генерация графика, кластеров и скринера.

Локальная среда проверки — Python 3.14; синтаксис дополнительно проверен для Python 3.12, указанного в Dockerfile. Сборка Docker и живое сравнение на Bothost не выполнялись. Это исправление статистики и рыночных данных; оно не означает устранение всех остальных замечаний из предыдущего аудита безопасности.
